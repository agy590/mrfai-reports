MrFai 的 Agent 笔记

Agent 不会因为更聪明而更可靠，它会因为更守规矩而更可靠

2026-11-07 · 主题：AI Agent 与多 Agent 协作

上周我把一个本该二十分钟做完的任务交给了 Agent，结果来回跑了四轮还没收敛。复盘下来，问题不在模型能力，而在我把一句话当成了规格。

我当时的任务是「把这个模块重构一下」。Agent 给出计划、改代码、跑测试，然后自己宣布完成。我看了报告，觉得合理，就放过去了。后来复核发现，其中一个改动悄悄绕过了错误处理，测试也只覆盖了新加的那条快乐路径。

这件事让我确认了一个判断：Agent 的可靠性不来自它更聪明，而来自任务被写成了可验收的契约。当目标、边界和验收标准全留在脑子里时，Agent 只能靠猜，而它猜错之后，还会用同样自信的语气汇报。

失败往往发生在同一个位置：规划、执行、验收被塞进同一个任务里。规划者给自己定标准，验收时又用同一套标准复核自己的产出，于是每一次都「通过」。这也是多 Agent 协作里最常见的假象——角色分了，独立性没有。

现在我的做法是这样的：

  1. 先写验收标准，再写任务描述。测试命令、期望输出、必须保持不变的接口，都放进同一份文本里。
  2. 把规划和验收拆成两次独立调用，验收方只看结果和原始需求，不看规划时的推理过程。
  3. 工具与路径默认最小授权，能只读就不要给写，能加白名单就不要整目录。
  4. 把这次踩的坑写回提示词，让同一个失败只发生一次。

第 4 步最容易被跳过，但它才是复利所在。否则你只是在重复支付同一次犯错的时间。
