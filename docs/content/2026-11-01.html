Agent 不是更聪明的同事，是更严格的执行器

2026-11-01 · 主题：AI Agent 工程实践

做 Agent 一年多，我踩过最多的坑不是模型答错，而是任务从一开始就没被定义清楚。同事给我一句模糊需求，我会回头追问；Agent 不会追问，它会自信地交出一份看起来很像样、但根本无法验收的产物。

最常见的两种翻车方式：让它改一个模块，它顺手重构了另外两个文件；让它写一份报告，它编了一组好看却不存在的数字。根因是同一个——我把「目标」当成了「规格」。目标说明要去哪儿，规格才说明怎么算到了。

所以我现在把 Agent 当执行器，不当大脑。执行器不怕笨，怕的是指令含糊。

一个具体的工程经验：交付任何任务时，最值钱的一句话是「完成后运行这条命令，并把真实输出贴出来」。加上这条，任务一次过的比例明显上升；不加，几乎每件都要我返工。因为输出无法伪造，而「已完成」三个字可以。

还有一条经验同样有效：如果任务涉及多个文件，先只给它一个文件的修改范围，跑通再逐个扩大。范围一旦放开，Agent 的注意力就会从「改对」滑向「改多」，而多出来的改动通常都是你不需要的。

今天就能试的 4 步

  1. 写验收标准：两条能判定真假的条件，加一条可执行的验证命令。删掉「做好」「优化一下」这类词，它们对模型等于没说。
  2. 控制范围：一次只允许改一个文件或一个模块，验收通过后再扩大。
  3. 要证据：要求贴出命令与真实 stdout，不接受「我已经完成了」的复述作为交付。
  4. 最后回读：让 Agent 重新读取产物，列出它做过的假设与未覆盖的分支，你来挑刺。
