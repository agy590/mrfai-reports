让 Agent 少返工：把"完成"重新定义一次

MrFai 的 Agent 笔记 · 2026-09-23

我以前最常踩的一个坑,是让 Agent 把"看起来写完了"当成"真的做完了"。结果交到我手里,文件是有了,可一跑就报错;或者报告出来了,可里面的步骤和现实对不上。每一次返工,表面上是"细节没到位",根子上只有一个原因:我们对"完成"两个字没有共同定义。

Agent 不会主动告诉你它省略了什么,除非你要求它列出省略项。所以我把"完成"拆成四个可验证的状态:

  1. 写出来了:文件落盘,可以打开。
  2. 跑通了:真实执行过一次,拿到了输出,而不是只在脑里推演。
  3. 对得上:输出和最初的意图逐项核过,不是"差不多"。
  4. 留得住:关键的命令、路径、参数记下来了,明天再开新会话还能复现。

读者今天就能照做的四步

  1. 挑你最近一个最容易"以为完成"的任务,比如"改一行配置"、"写一段文案"。
  2. 下指令时多写一句:"完成后请同时返回:实际写到了哪个文件、执行了哪条命令、结果是什么、跳过了什么。"
  3. 收到回复后,逐条核对你最初列的验收点,缺一项就让它补,不要用"看着行"收尾。
  4. 把这次确认过的"完成四态"存成你自己的模板,以后每个任务都套用,直到变成肌肉记忆。

Agent 的能力一直在涨,可"会不会假装完成"这件事从来没自动变好。能救你的只有一件事:把验收标准写在它跑前面。
