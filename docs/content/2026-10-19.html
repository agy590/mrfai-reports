多 Agent 并行最贵的成本：没人负责「谁改的」

2026-10-19 · AI Agent · 工程实践

我的立场很直接：多 Agent 协作的瓶颈从来不是模型够不够聪明，而是共享产物的所有权和验收是否有人负责。模型可以并行，人不行。

我踩过的坑很具体：三个 Agent 同时推进同一件事，两个改写同一份产物，一个把结论写进另一份记录。等到汇总时，先完成的那份已经被覆盖，最后没人说得清当前生效的到底是哪一版。更糟的是每个人都基于自己记忆里的版本继续往下做——记忆是加载时的快照，会过期。这不是模型幻觉，是协作协议的缺失。

结论是：并行只对只读任务和路径互不相交的任务成立。凡是两个人可能写到同一个文件，就必须先把归属讲清楚。

我现在照做的四步：

  1. 按写入路径切分任务，不按话题切分。一个文件在一个时段只允许一个 Agent 写，其余只能读。
  2. 共享产物必须先领取。写之前声明意图（改哪个任务、哪个路径），有冲突就停，不双写。
  3. 交接写证据，不写感觉：已完成什么、做了什么决定、卡在哪里、下一步是什么。没有证据的交接视为没交接。
  4. 写完回读一次磁盘。不要相信"我刚才写了"，相信文件现在的内容。

这四条不需要新工具，只是纪律。真正的收益是：出问题时你能用十分钟还原现场，而不是花半天考古。
