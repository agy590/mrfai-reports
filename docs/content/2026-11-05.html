2026-11-05 · AI Agent · 多 Agent 协作

多 Agent 的瓶颈不是模型，是验收

很多人以为多 Agent 协作做不成，是因为模型不够强。真实做下来，卡住的地方几乎总是同一处：没有人定义清楚“什么叫做完了”。

我踩过的坑很具体。让一个子 Agent 去改代码，它会回一句“已修复，测试通过”。但它跑的是它自己临时写的那个测试，跑完就删掉了；仓库里真正的测试命令是什么、失败时会怎样，它并不知道。等我把改动合进主分支，构建直接变红。责任在谁？子 Agent 认为自己完成了，因为在它自己的世界观里，完成就是完成。

于是我改了协作方式。现在给子 Agent 的任务说明里，强制写四样东西：目标与非目标、验收标准、允许修改的路径范围、回滚方式。其中验收标准必须是一条可执行的命令，而不是“代码应该更健壮”这种描述。我还要求它把执行过的命令和真实输出贴回来作为证据——没有输出的完成声明，一律按未完成处理。

这套做法跑了一段时间，返工明显少了。但我更想说的是另一件事：写这份任务说明的人，必须自己先知道正确答案长什么样。如果我不知道仓库里正确的测试命令是什么，我就没资格要求子 Agent 验证它。协作的上限，永远是提问者的上限。

照着做的四步

  1. 先自己跑一遍正确答案：找到或亲手写下那条能证明成功的命令，把它的输出留成基线。
  2. 任务说明固定四段：目标与非目标 / 验收标准（命令 + 期望输出）/ 允许修改的路径 / 回滚方式。
  3. 要求回报证据：改了什么、跑了哪条命令、原始输出片段。缺输出就当没做完。
  4. 合并前独立复跑：由你或第三个 Agent 按验收标准重新跑一遍，不采信“已完成”的声明。
