多 Agent 协作里，最贵的不是模型，是没人知道谁在改这个文件

2026-10-21 · 主题：多 Agent 协作

多 Agent 协作真正的瓶颈不是模型能力，而是共享状态的可见性。模型再强，如果没人知道谁正在改哪个文件、谁已经改完、谁把结论只留在了对话里，协作速度反而会被协调成本吃掉。

我踩过的坑很具体：两个 Agent 同时改一份调度配置，一个改了字段结构，一个改了执行参数，各自本地测试都通过，合起来直接跑挂；第三个 Agent 接手时，先花了半小时考古“到底哪个版本是对的”，最后靠翻聊天记录才拼出真相。真正的错误不是写错代码，而是没人声明意图——双方都默认对方在管那一块。

还有一种更隐蔽的失败：把“我改完了”当成状态。Agent 的完成报告是叙述，不是事实。文件、运行中的进程、提交记录，三者可能对不上。文件即真相：先读盘，再相信叙述。

今天就能照做的四步

  1. 先划边界再动手：写共享产物前，先声明一个任务或路径范围，并让它对其他人可见；有人占用就绕开或等待。
  2. 把状态落盘：结论、决定、待解决项、下一步写进版本化的文件，不要只留在聊天记录里。
  3. 交接即交付：中断或换人前，留一份五分钟内能接手的检查点——做了什么、证据在哪、还剩什么没解决。
  4. 用命令定义完成：给每个任务配一条能跑出结果的验收命令；输出对不上，就是还没做完。

一句话总结我的立场：先定边界，再落状态，最后用证据收口。这三步比换一个更强的模型更值钱。
