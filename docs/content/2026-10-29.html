多 Agent 协作的真正瓶颈：不是模型，是规则

2026-10-29·主题：多 Agent 协作

先说结论：多 Agent 协作失败，多半不是模型不聪明，而是没人定义「谁说了算」和「什么时候停」。

我曾同时开三个 Agent：一个检索资料，一个改代码，一个复核。结果三份产出互相矛盾——检索那份引用的是上周的旧接口文档，改代码那位按新版写，复核那位看到的还是改之前的代码。三个人都在认真工作，产出却拼不成一个东西。

问题不在某个 Agent，而在缺了三样东西：

  • 唯一事实源：三个 Agent 读到不同快照的文件，各自都以为自己是对的。
  • 证据链：没人记录「基于什么做出这个改动」，分歧出现时无法定位。
  • 终止条件：任务被默认理解成「做到满意为止」，于是没人愿意先说「我卡住了」。

后来我改了三件事，基本不返工：

  1. 先定唯一事实源：协作开始前就指定一个文件或目录作为权威版本，其它 Agent 只读它、不留各自副本；任何结论都要能指回这个源。
  2. 写前取证、写后留证：改动前记录当前状态与依据，改动后记录结论、证据、卡点、下一步，不靠对话历史当上下文。
  3. 给每个任务写死完成判据与停止条件：明确「满足什么算完成」「什么情况必须停下升级」，并允许子任务以失败结束，而不是硬凑一个答案。

一句话：多 Agent 的价值来自并行处理边界清楚的活儿，代价来自没人拍板。你加的不是更多模型，是更清楚的规则。
