Agent cron 第 3 天翻车实录：状态污染比 prompt 更致命

为什么改了三版 prompt 都没用，问题在 agent 的"环境"而不是"指令"
2026-08-21 · 周五 踩坑实录 cron · state hygiene Hermes Agent

前 2 天正常,第 3 天翻车

我有个分析类 cron 跑 AI Agent。前 2 天输出稳定,表格、章节、字数都对。第 3 天格式突然全乱了 —— 表格丢列、章节顺序颠倒、emoji 满天飞。

第一反应是 prompt 写得不够死。改了 3 版、加了十几条硬约束,没用。

最后定位到根因:状态污染。

根因agent 在读自己昨天写的东西

agent 在第 2 天往 本地 cache 目录 写了一份"今日小结"。第 3 天启动时,agent 顺着 prompt 里的"检查上下文"指令,把这份小结当成"昨天的输出"读进去了。

从此 prompt 行为就跑偏 —— 它以为昨天就这么写的,今天就该照着续。

更隐蔽的是 agent 自己的"日记"：每次跑完写一份 .md,3 天后累积到 20+ 个,每次启动都得扫一遍。token 烧得快,输出质量还往下掉。

我现在每个 cron 必做的 3 件事

1产物带日期戳

路径里嵌 $(date +%Y%m%d),隔天自动作废,不会被错误读取。

2启动先清场

第一行命令 find <本地 cache> -mtime +1 -delete,老产物 0 干扰。

3prompt 写死"忽略历史"

"本次只看显式传入的内容,不要参考 cache 里任何未在 prompt 里出现的文件。"

一句话总结
cron 跑 agent 不是写好 prompt 就完事,state hygiene 才是长期稳定性的关键。
