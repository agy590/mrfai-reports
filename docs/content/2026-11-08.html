多 Agent 协作，先分清谁负责哪一段

2026-11-08 · 主题：多 Agent 协作与工程纪律

多 Agent 协作失败，八成不是模型不够聪明，而是没人先说清楚：这一段谁负责、什么时候算交付、拿什么验收。模型可以并行，边界必须由人先划好。

我踩过的坑很具体。两个 Agent 各自推进同一个共享文件，一个按旧状态写，另一个按新状态写，两份结果互相覆盖。等复核的时候，谁都坚持自己那份才是最终版——产物还在，结论没了。这种失败不报错，日志也干净，只有到最后一刻才暴露。

后来的做法是把顺序固定下来：共享内容先定一个事实源，写入前先读现状，动手的人各自认领一段互不重叠的路径，交接时固定留下证据、决定、卡点和下一步。谁该动哪一块，不再靠临时商量。

还有一个反直觉的收获：让「只验收、不实现」的角色独立复核，比让写代码的 Agent 自己检查更有效。复核者发现问题的能力和实现者不是一回事，同一个上下文里，人也会顺着自己的思路看顺眼。

可以照着做的四步

  1. 开工前先写十行以内的小计划：目标、明确不做的事、验收标准、允许改动的路径。
  2. 划清不可交叉的路径归属，谁负责哪段就只动那段，越界前先停下来确认。
  3. 交接固定留三行：做了什么、卡在哪里、下一步做什么，别让上下文只活在聊天记录里。
  4. 收尾交给独立复核者，只读不改；不通过的部分退回给执行者，不代劳。
