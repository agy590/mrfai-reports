多 Agent 协作真正的瓶颈是任务边界

2026-11-09 · 主题：多 Agent 协作与工程实践

多 Agent 协作最大的误解，是把「Agent 数量」当成能力本身。我自己的经验正好相反：Agent 越多，越容易出现没人认领的中间状态——每个人都干了一点，但没有人能说清整体到底完成到哪一步。

翻车过一次。我让一个 Agent 同时负责读代码、改代码、写复盘报告。它跑得很顺，日志也漂亮，交上来的是一份基于「我以为已经改好了」的结论。真实状态是只改了一半，另一半被它当成已完成写进了报告。问题不在模型，在任务边界：我给了一个动词（处理），却没说清哪些动作允许发生、什么才算完成。

修法不是换更强的模型，而是把边界写成机器能查的东西。四步就能落地：

  1. 三行边界：允许读什么、允许写什么、输出成什么格式。写不满三行，说明任务还没想清楚。
  2. 先只读，后写入：第一轮只产出结构化清单供人确认，确认后再开写入权限，别让同一个 Agent 自己给自己放行。
  3. 把「完成」写成一条可执行命令（跑测试、查字段、验产物），不要写自然语言验收标准。自然语言会漂移，命令不会。
  4. 连续两次产出不可用就停手改边界，别急着加并发、加 Agent、加 prompt 长度。堆数量只会把同一个模糊问题复制多份。

Agent 不像团队成员，更像一个只会照字面执行、而且永远很自信的新人。你怎么描述边界，决定了它能走多远。
