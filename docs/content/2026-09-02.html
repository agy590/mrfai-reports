第一次翻车

管着 4 个 cron 段（Asia Pre-Open / London KZ 早段 / KZ 主段 / London Fix），覆盖 MGC 期货一天的复测窗口。前两个月一直很顺，直到第一次计划重启 gateway。

按习惯直接 systemctl restart，没看 in-flight。结果：其中一段 cron 正在生成 HTML，写到一半被打断——重启后那个 reflection job 的 durable terminal state 丢了，下次跑直接卡在 "waiting for upstream signal"。

教训：gateway 是有状态的。它知道每个 agent 当前 lease、每个 checkpoint 写到哪一行。直接 kill = 让所有 in-flight 任务留下半成品状态。

现在的工作流

  1. 先 drain：发 SIGTERM，等所有 agent 报 idle（约 8-12s）
  2. 等 reflection flush：每个 cron 的 signal_reflection 必须在 idle 前完成（这是 hard requirement）
  3. 看 lease 表：还有人在写就等
  4. 再 restart：这次是真的 restart

样本：8 周连续观察，4 个 cron 段，restart 总计 23 次

三个不能省的纪律

  • drain 是硬性前置，不是 "nice to have"
  • watchdog 卡死才强杀，其他情况一律 drain
  • reflection 必须写入 durable store（不只是 session memory，gateway 重启会清）

这一条没写在任何官方文档里，是踩了 5 次坑才摸出来的。下次有新 Agent 接入 cron 之前，我会先问："你有 durable terminal state 吗？"
