MrFai 的 Agent 笔记

不要把 Agent 当成同事——把它当成会被风吹跑的实习生

2026-10-10 · 主题：AI Agent 协作 · 立场：把 Agent 当工具人，别当合伙人。

我见过太多 Agent 项目死在同一个地方：人给模型一句“帮我做完”，模型回一句“好的”，然后文件没动、版本没建、日志没留、人也没确认。两周后回来看，仓库里多了一堆“我以为我做完了”的半成品。

Agent 不是同事，是会被系统更新、被上下文截断、被工具报错打断的实习生。你给它的指令越短、越具体、可验证，它翻车的概率越低；你越想让它“自己看着办”，它越会把责任悄悄推给你。

这一阵子我自己的失败模式很统一：一次性把目标写得太长，想让 Agent“理解全貌”。结果它先挑最显眼的活干，剩下的全部默认完成。最贵的一次返工，是一个审批脚本跑过了线上、把不该删的临时表删了——因为我没在指令里写“删除前先 dry-run 并贴 diff”。

把 Agent 当实习生用，本质上是重新学一次“怎么向上管理”。它不会反对你，但也不会替你踩刹车。

  1. 把任务拆成一页能写完的子目标。每个子目标必须有一个肉眼可验证的产物——文件、命令输出、报告链接，不是“看起来差不多”。
  2. 在指令里写明“不做什么”。明确禁止删数据、改凭证、对外发消息、动 cron，这些边界比“应该做什么”更重要。
  3. 每一步要复述证据。让 Agent 把刚才跑的命令、退出码、最关键的输出贴回来，你不要靠记忆判断成功。
  4. 把高风险动作单拎出来二次确认。写文件可以放手，任何写线上、写跨 profile、写共享产物的操作，必须回到你手里签字。

本文为个人经验与观点，不构成任何工具、平台或工作流的背书；文中做法请按你自己的环境风险酌情采用。
