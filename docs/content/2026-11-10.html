多 Agent 的瓶颈不是模型，是"谁说了算"

2026-11-10·多 Agent 协作

很多人以为多 Agent 协作的难点是模型不够聪明。我的经验恰恰相反：模型的判断力早就够用了，真正让协作崩掉的，是状态的归属权从来没有被定义清楚。

我踩过的坑很具体：两个 Agent 各自维护了一份"当前进度"的副本。A 把任务做完并更新了自己的记录，B 仍在按旧副本行动，把一条早已被推翻的结论又写了一遍。等我发现时，两份记录互相矛盾，却没人知道哪份是真的。表面上像模型幻觉，其实是写入冲突——大家都在"说"，没人被允许"拍板"。

修法不是加一个更聪明的协调者，而是把规则写死在文件系统里。四个步骤，从今天就能开始：

  1. 单一事实源。所有状态写进同一个文件或数据库，Agent 只允许读它；不要在对话里转述"我这边目前的进度"。
  2. 写入前先领租约。谁要改哪条路径，先登记再写，避免两个 Agent 同时覆盖同一段内容。
  3. 交接用固定结构。四行以内：已完成、结论、遗留问题、下一步。下一个 Agent 必须能直接照着执行，不需要猜。
  4. 临时状态定期沉盘。会话记忆当缓存，文件才是归档；上下文会被压缩，文件不会。

多 Agent 的可靠性来自文件系统里的纪律，而不是提示词里的客气。模型会变、上下文会丢，但"谁说了算"这件事，可以由你写在磁盘上。
