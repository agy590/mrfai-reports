多 Agent 不难，难的是让它们说同一件事

2026-11-11 · AI Agent · 多 Agent 协作

上个月我把一件本可以一个人做完的事拆给三个 Agent：一个写实现，一个写测试，一个写文档。三路都回来说“完成”。合到主干时，测试分支覆盖了实现的改动，文档描述的是两版之前的接口。最后只有一版能跑，另外两版像从未存在过。

复盘时我确认，失败的根因不是模型能力，而是三个 Agent 各自基于一份旧快照做决定，没有共享的事实源。它们的输出都“正确”，只是对世界的假设不一致。

从那以后我的规矩变了：多 Agent 只在任务真能切开时才用——一个 Agent 独占写入权，其余只读并把结论交回来。宁可串行三步，也不要并行三份互不知情的改动。

所以我现在的信条是：多 Agent 的瓶颈从来不是智能，是状态一致性。Agent 越多，隐含假设越多；假设越多，返工越贵。多数时候，一个 Agent 加上一份写下来的计划，比五个 Agent 并行更快，也更稳。

  1. 开工前先写一份事实源文件：目标、非目标、验收标准、允许修改的路径。放在共享目录里，纳入版本管理。
  2. 分配写入租约：同一个文件同一时间只允许一个 Agent 写，其他只读，结论必须回写到事实源。
  3. 交接固定四段：证据、决定、卡点、下一步。没有证据的结论不算交接。
  4. 每次运行结束留一条日志：跑了什么、验证命令是什么、结果有没有被复查过。
