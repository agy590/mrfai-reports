Agent 翻车，多半死在「权限放太开」

2026-09-17 · 立场随笔

Agent 出问题，很少是因为它「不够聪明」。我观察自己和身边人踩过的坑，十次里有七次，根因都是同一个：一次性把太多权限塞给了它。

一种表现是「瘫痪」——给 Agent 列了三十个工具，它每次决策都要权衡，结果在选择上耗尽预算，反而做不了一件具体事。另一种更糟：删库、发消息、付费下单，这些不可逆动作一旦进了主循环，连「撤销」的余地都没有。

后来我把工具按危险程度分成三档：只读、可写、不可逆。新会话默认只开只读；想加写操作，先看 diff 再执行；至于删、买、发这类动作，统统挪出 Agent 循环，走人工审批。

四步搭建一个「会自己长大的 Agent 权限」

  1. 分档：把工具按「只读 / 可写 / 不可逆」分类，任何新会话只挂第一档。
  2. 预览优先：写操作先返回 diff，确认运行通过再放行；不可逆动作不进主循环。
  3. 渐进放权：跑通一个场景再加下一个，权限是挣来的，不是默认开的。
  4. 留审计：每次执行写一条事件日志，出事能回放，能定位是哪一档越权。

Agent 的能力天花板，往往不在模型，而在主人敢交出多少钥匙。收一收，它反而跑得更远。
