按可逆性给 Agent 分级授权，而不是按任务重要性

2026-10-17 · AI Agent · 工程实践

很多人给 AI Agent 定权限时，问的第一个问题是：这个任务重不重要？重不重要其实是个坏标尺。同样是"改一行代码"和"改一行配置"，前者错了能撤回，后者错了可能让整套环境跑不起来；而"整理文档"看着轻，一旦它顺手删掉一个目录，就完全不可逆。

我的立场更直接：授权的粒度应该由动作的可逆性决定，而不是由任务听起来有多重要决定。同一个任务里，允许写临时文件、允许改工作区代码、允许碰用户配置、允许对外发消息，这四件事必须拆成四种授权，而不是打包成"帮我搞定这个"。

我踩过最贵的一次坑，不是模型答错了，而是它答得太对：它发现一批旧日志没被引用，顺手清理了。那批日志当时没有任何引用关系，但它们是回滚某次发布时唯一的现场记录。要恢复，只能靠更早的备份。我当时唯一的念头是：任务本身没出错，错在我把"清理"和"记录"归成了同一档授权。

从那以后我固定这么做，四步：

  • 先列出这个任务会触碰的所有写操作路径，一个一个标上可逆还是不可逆。标不出来的，默认按不可逆处理。
  • 把不可逆动作从任务里拆出去。要么明确告诉 Agent "只报告不执行"，要么就明确授权它执行——不允许含糊。
  • 在提示里给它一条硬规则：删除前必须先打印清单等确认。不是每次都拦，而是让"要删什么"成为它主动说出来的事。
  • 把每次不可逆操作的命令和结果留在日志里。出事时你需要的不是复盘它的推理过程，而是"当时到底执行了什么"。

这套做法的额外好处是，你终于能判断一个任务"成功"了没有。以前 Agent 说"已完成"你只能信，现在你能自己复现最后三步。对一个要长期跑的系统来说，这个差别比模型再聪明一代都重要。
