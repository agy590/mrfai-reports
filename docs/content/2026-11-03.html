多 Agent 的瓶颈不在模型能力，而在交接质量

2026-11-03 · 主题：多 Agent 协作

这几年我复盘过的代理任务崩掉，原因大多不是“模型不够聪明”，而是信息在交接那一步丢了。

多 Agent 看起来像流水线：规划、执行、审查，各由独立上下文窗口干活。但流水线的接口不是自然语言，而是产物。规划者写一句“按计划执行”，执行者拿到的是一句话加一段被截断的历史；审查者看到的是执行者的自我描述，而不是它实际动过的文件。

我踩过的坑：后台任务回报“已完成，测试通过”，可产物根本没落盘。根因是执行方把“我认为完成了”当成了“完成了”。完成状态只能由外部证据决定，不能由执行者自述决定。

另一个隐形坑：子 Agent 会用假设补齐拿不到的信息，再把假设写成事实。你没法靠“再问一次”解决，因为你不知道哪句是编的。任务里必须预留“阻塞”这个出口。

多 Agent 的价值不是让更多模型同时说话，而是让每一次交接都不必靠信任。下面四步是我现在每个项目都在做的。

  1. 每个子任务只配一个产物路径，配一条能机器判定成败的验收命令：测试、构建、哈希校验都行。
  2. 交接一律落文件，固定四段：做了什么、证据在哪、还差什么、下一步。
  3. 审查只看一手证据：文件内容、命令输出、diff。摘要只是线索，不是结论。
  4. 缺信息就写成显式阻塞项，不要靠推断补齐。“数据缺失”是状态，不是错误。
