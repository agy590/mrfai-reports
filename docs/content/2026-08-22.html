最隐蔽的失败：做对了但没人用

跑了半年多 Agent 自动化，我观察到的最隐蔽的失败模式不是「做错」，是「做对了但没人用」。

循环长这样：agent 给老板（也就是我自己）出方案 → 方案被搁置 → agent 不知道被搁置 → 下一轮又出一份类似方案 → 又被搁置。

这种「沉默的浪费」在 cron 场景特别致命。白天 cron 跑出 5 份方案、没回，到晚上积压了 3 天的素材，每一份都没落地。

怎么破：一条 SOUL 规则

我在自己的 Agent SOUL 里加了一条规则，原文：

「当你产出的方案、计划、或建议连续三次未被采纳、未被执行、未产生行动时，反馈环就断了。这时候不能默默继续输出。」

触发的三步动作

  • 复盘：是输出质量不够好？还是方向就不对？
  • 调格式：太长？太短？切入点不对？
  • 主动喊停：「这份方案我出了三次，目前都没落地。要不要换个方向？」

关键不是「少做事」，是「每次输出都验一下对方到底看了没」。

从 Google 思维到 PMF 思维

Agent 不是搜索引擎。你给 100 个结果，对方一个都不用，比你给 1 个精准结果糟糕得多。

把这条规则抽出来就是一句话：反馈环就是 Agent 的产品市场契合度（PMF）——没人用，就什么都不是。

三个可立刻落地的动作

  • 每条 cron 任务输出加一个「是否落地」回执字段
  • 把长报告压成「标题 + 一句话摘要 + 链接」三件套
  • 给 Agent 配一个「沉默计数器」，连续 N 次无响应自动停跑

写在最后

如果你也在跑 Agent 自动化，最该问的不是「agent 能做更多吗」，而是「agent 上次输出的东西，我真的看了吗」。

看完率、采纳率、转化率——这三个数字比模型能力更重要。能力是天花板，反馈环是地板；地板塌了，天花板再高也没用。
