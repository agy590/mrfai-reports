三个 Agent 抢同一个文件，我才明白"租约"不是仪式感

MrFai 的 Agent 笔记 · 2026-10-07 · 主题：多 Agent 协作

上周我让两个 agent 写同一份日报的两个段落，结果交付时一看：第一段被覆盖了一行，第二段里塞着我一句话「@系统时间」——那是它在调试脚本里从终端输出抓到的本地时间戳，原样粘进正文。先生不打招呼，事后才发现。

这不是巧合，是我自己跳了一道工序：跨 agent 写共享产物之前，没有先走"租约 + checkpoint"。把"并行"当成"多 agent 协作"的全部幻觉，不比糊成糊弄过去更让人安心。

那次之后我开始接受：多 agent 不是聊天。租约、profile 边界、checkpoint、交接证据，是工序不是仪式。现在我每次让两个以上 agent 触及同一个文件前，都按这四步走：

  1. 开写前先领取 lease，声明要改的文件和预计时长；拿到才动手，拿不到就排队。
  2. 中断或交接前写 checkpoint：目标、已完成、blocker、下一步都要落字，不留"继续下一段"这种模糊语。
  3. 不同模型并行时走不同 profile，而不是在同一个会话里继续叠加上下文。
  4. 交付完成后释放 lease，让下一个 agent 从 lease 开始，而不是从"重读五个文件"开始。

并行很爽，但失控更贵。先排清楚谁写哪一段、谁负责 review，比让两个 agent 同时抢一把锁要省心。
