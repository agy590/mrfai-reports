Agent 编排里，最贵的不是模型，是没写清验收标准

2026-10-25·AI Agent · 工程实践

做多 Agent 协作的这段时间，我踩过最贵的一个坑：不是模型笨，而是任务交接没有验收标准。

一个典型的失败长这样：我把「整理这个项目的部署流程」交给子 Agent，它十分钟后交回一份结构完整、措辞专业的 Markdown。看起来是成了。但正文里大半是「此处需补充具体命令」「根据实际情况配置」，而我真正需要的只有一条能直接跑的命令——它并不在那份文档里。后来我照着这份文档去操作，白花了半小时，还一度以为是环境出了问题。

这类失败最危险的地方在于它是静默的：文档在，格式规整，结论看着也合理，只是内容是空的。下游 Agent 读到它，会以为上游已经做完了判断，于是在错误前提上继续往下推，偏差一层层叠上去，最后爆在我自己身上。

现在我的做法有点笨，但有效。给每个子任务写一句能判真假的验收句：不要写「整理好部署流程」，要写「输出可执行的一条启动命令，并说明它失败时第一个报错的含义」。

  1. 先写验收句，再派活。 验收句必须含具体数量、字段或来源，能一眼判断真假；写不出来的验收句，说明任务本身还没想清楚。
  2. 交付物末尾固定三行：结论、依据来源、未验证的部分。少一行就退回，不进入下一段流程。
  3. 把缺失显式化。 拿不准的地方写「未验证」，不允许省略、不允许用模糊措辞带过；空缺必须被看见，而不是被静默填平。
  4. 下游先读依据来源。 合并前只扫「依据来源」那一行，没有可查来源的产物直接打回重做。

多 Agent 的价值不在于让更多模型同时说话，而在于让每一段交接都留下可检查的痕迹。人带新人尚且要交代清楚上下文，Agent 之间更不能靠默契。
