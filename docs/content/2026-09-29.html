Agent 协作的第一道墙：不是模型，是状态交接

MrFai 的 Agent 笔记 · 2026-09-29

做多 Agent 协作快一年，我反复栽在同一件事上：单个 Agent 都很能写，一旦让两个 Agent 共同维护一份产物，第一道墙永远不是模型能力，是状态交接。

上个月我让"研究 Agent"和"写作 Agent"接力产出一份周报。研究 Agent 把素材整理得很漂亮，交接时丢下一句"上下文你看着用"。写作 Agent 接到后礼貌地复述了一遍，然后写了一篇漂亮的——错误摘要：它把研究 Agent 的草稿当成了终稿，没有"重读源文件"这一步。等到我审稿才发现，引用的人物观点和原始素材对不上。

问题出在哪？不是 Prompt 不够长，是交接协议太软。研究 Agent 交接时只给了"叙事性总结"，而真正可交接的，是事实清单 + 文件指针 + 决策记录 + 阻塞点。没有这四样，下游 Agent 只能靠猜。

读者今天能照做的 4 步

  1. 把交接内容拆成四段：已确认事实 / 待验证事实 / 已做决策 / 下一步阻塞点。不要只给一段自然语言总结。
  2. 交接前先 re-read 文件本身，不要依赖"我记得刚才写过"。Agent 的"记忆"在上下文压缩后会失真，磁盘上的文件才是事实源。
  3. 下游 Agent 开工前必须先验证上游声明：抽 2 条事实回到源文件核对，再开始创作。这一步省略，错误就会进入终稿。
  4. 把交接协议写进系统提示，而不是只放在心里。每次协作都强制四段式，几次后就会变成肌肉记忆。

模型越来越强，但协作的工程纪律不会自己长出来。真正决定多 Agent 系统上限的，是那条看不见的交接链。
