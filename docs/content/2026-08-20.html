为什么我把角色 prompt 注入,而不是写进永久 system

📅 2026-08-20 · MrFai 的 Agent 笔记 · 来源: 实际 cron 运行经验
跑了半年的多 Agent cron,我学到的最反直觉的一课:把"投资研究员"的角色 prompt 写进永久 system 里,反而会让所有输出风格都被污染。

事情是这样的。我最早做定时任务的时候,图省事,把常用的几个角色身份(分析师、复盘员、内容创作者)直接拼进 SOUL 里。心想反正都是每天要用的,固化下来多好。

结果跑了一个月就翻车了。

翻车现场

某天我让 cron 跑一个"独立开发工具链盘点"的内容任务。系统 prompt 里因为还挂着"投资研究员"的工作原则(冷静、数据先行、风险提示),输出出来的内容变得:

  • 干巴巴的,像在读研报
  • 每段都要插一句"风险提示"
  • 完全没有"我在用这个工具"的温度

复盘任务也出问题——内容任务跑出来带"叙事张力",复盘任务却失去了数字感。

问题根源:永久 system 是常驻的,角色身份会渗透,互相污染。

我的解决方案:每次任务重新注入

后来我把所有角色 prompt 移到本地一个按 category 分目录的角色库(每个角色一个 markdown 文件)里,做成可加载的资源。cron prompt 里只加一句:

## 角色身份(必走)
执行前调用 load-agent-role skill 加载 marketing/content-creator,
以该身份完成任务。

每次跑 cron,系统先读角色文件,把身份声明和核心工作原则(摘要后约 500-1500 字)注入到当前 system prompt 头部,跑完就丢,不残留。

这套打法的好处
身份隔离度
↑ 95%
风格残留
↓ 接近 0
角色切换成本
1 行 prompt
  • 身份隔离:复盘任务跑出来就是冷冰冰的数据 + 风险提示,内容任务跑出来就有 hook、有 CTA。互不干扰。
  • 可调优:角色 prompt 是单文件,改一处就影响所有引用它的 cron,不用碰 SOUL。
  • 可复用:同一个角色可以被不同任务加载,加载摘要怎么取(只取"身份+核心使命+关键规则"三节)由调用方控制。
  • 避免永久 system 膨胀:SOUL 只放跨任务的元规则(反对要带数据、不写空话、沟通风格),不放领域知识。
一句话总结

永久 system 放价值观(做事的态度),角色 prompt 放角色身份(做事的方法)。前者常驻,后者按需注入。这条边界划清后,我的多 Agent cron 风格污染问题就消失了。

如果你也在做多 Agent cron,试试这个模式。把所有领域知识从 SOUL 里剥出来,变成可加载的 skill,只在需要时调进来。
