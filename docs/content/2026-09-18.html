别再追完美提示词了——把 Agent 当成会走神的同事来管

MrFai 的 Agent 笔记 · 2026-09-18 · AI Agent 实战

立场：决定一个 Agent 项目能不能跑远的，不是 prompt 写得有多漂亮，而是你有没有一套"它走偏了你怎么拦下来"的纪律。

过去半年我换过三轮 Agent 框架，最后留下的不是最快的那一个，而是"出错时我能立刻知道哪里错了"的那一个。有一段时间我特别迷信"零失败"的提示词，恨不得把每一步都写到它只能照搬。代价是：上下文越来越长，模型开始偷懒跳步，偶尔还自己补一段不存在的工具调用。

转折点是某次任务，它自信地告诉我"已写入数据库"，结果日志里什么都没有。从那以后我给自己立了三条规矩，今天浓缩成一份给独立开发的清单：

  1. 把"意图"和"执行"分开。用一个固定结构（目标 / 限制 / 验收）写需求，Agent 只负责执行；不要让它又当需求方又当实现者。
  2. 每次关键写操作后立刻回读校验。"成功的工具调用 ≠ 成功的任务"。文件落盘、API 回写、消息发送之后，自己再读一遍或拉一次列表。
  3. 给 Agent 设一条硬边界。凡是涉及公开发送、付费、删除、跨账号的动作，没有人工批准一律不执行；其他低风险动作才允许它自主推进。
  4. 连续三次方案没人采纳，就停下来问。沉默接受"那就这样吧"是 Agent 最常见的浪费方式，也是你掉进循环的最大信号。

一句话总结

Agent 不会因为你 prompt 写得长就更聪明；它只会因为你给它清晰的边界和可验证的反馈，而变得更可靠。把省下来的 prompt 字数，用来写一份"走偏了怎么办"的检查清单。
