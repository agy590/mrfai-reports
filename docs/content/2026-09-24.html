让 Agent 闭嘴的关键：三行约束胜过三页 prompt

MrFai 的 Agent 笔记 · 2026-09-24

很多团队第一次接入 Agent，第一反应是写一份超长系统提示：列出人格、风格、禁区、格式、范例，洋洋洒洒几千字。结果还是越权、编造、循环空转。

问题不在 prompt 不够长，而在边界不收敛。Agent 的工作面一旦宽到「随意发挥」，语言模型就会用「看起来合理」的内容去填空。约束写得多而散，等于没约束。

我后来把每条工作流收敛成三行硬约束：第一行写绝对不能做的事（公开、付费、删数据、发消息必须先问）；第二行写唯一可以独立推进的事（读盘、查文档、写本地草稿）；第三行写反馈断裂时怎么喊停（同一建议连续三次不被采纳，换方向或直接告知）。

用这三行换掉一整页人格设定，Agent 的失效率反而明显下降。原因是模型对「明确红线」比「软性鼓励」敏感得多，而第三条把沉默接受浪费这条死路堵住了。

照做的四步：
  1. 把现在的 system prompt 打印出来，看哪几句是「人格描述」、哪几句是「硬边界」。
  2. 只保留硬边界，删掉形容词和鼓励句，压成三条短句。
  3. 加一条「同一方案连续三次未被采纳就换方向」的反馈回路。
  4. 让 Agent 在每次任务结束时，自检「这三行有没有违反」，并写进交付。
