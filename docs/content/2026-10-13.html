多 Agent 协作的真正瓶颈，不是模型，是协议

2026-10-13 · AI Agent · 多 Agent 协作

很多人把"多 Agent 协作"想得太浪漫：拆任务、分工，模型各自发挥，最后拼一份漂亮的结果。现实里卡住协作的，从来不是某个模型够不够聪明，而是几个 Agent 之间有没有一份能强制执行的协议。

我最近一次复盘里看到典型失败：A 子 Agent 正在改一个配置模块，B 子 Agent 同时去同步第三方依赖。两者没声明"我现在占用哪个文件/路径"，结果 B 把 A 还没写完的导入结构直接覆盖了。日志没报错，单元测试还是绿的，最后交付出的是一份能跑但语义错的版本。

这件事让我确信一件事：模型越强，错误越安静。强模型会写出语法正确、看起来合理的"伪成功"，不靠协议截停，根本察觉不到。

所以如果你正打算把工作流从单体 Agent 拆成多 Agent，先别急着上框架，先把下面四件事做扎实：

  1. 先画边界。把任务拆成"谁写、谁读、谁删"三类，对应一份显式的 lease，没有 lease 就不动文件。
  2. SSOT 优先。每个 Agent 操作前先读权威源（README、registry、状态文件），不靠记忆，也不靠上一次的聊天结论。
  3. 每一轮留证据。每次动作都要写出 evidence（看到了什么）+ decision（决定做什么）+ blocker（卡在哪）+ next（下一步）。交接包就是这几样，不是聊天截图。
  4. 终验要独立。验收交给第三个 Agent 或独立 review，收到 PASS 才算结束；执行者自己给自己打 PASS 不算 PASS。

这四件事没有银弹，但缺任何一件，多 Agent 系统都会"看起来没事地"安静坏掉。先把协议定死，再去谈哪个模型更强。
