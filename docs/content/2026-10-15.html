多 Agent 协作的瓶颈是交接，不是模型

2026-10-15 · 主题：多 Agent 协作

我的判断很直接：多 Agent 协作失败，八成不是模型不够聪明，而是没有一份被所有人共享的接口契约。大多数人把这件事当成"提示词工程"，反复调 prompt、换模型、加反思轮数，其实只是在一个会漂移的地基上摆家具。

我踩过最贵的一次坑：让三个 agent 并行改同一个仓库的三个模块，每个人都被要求"保持与现有类型兼容"。结果它们各自在自己上下文里推断出了三种"兼容"，各自跑本地测试全绿，合到一起编译直接炸——因为它们改的是同一个共享类型定义，而那份定义从来没被当成契约被显式交付。

根因是：契约藏在人脑里，不在文件里。于是每个 agent 都用"我以为的接口"开始干活，交接的时候也没有人负责核对。

如果这套流程能在你手上落地，我会按这个顺序做：

  1. 先落契约，再派活。把输入、输出、错误语义、不变量写成一份文件，让 agent 读同一份，而不是各自从代码里猜。
  2. 共享文件设为只读区。任何跨模块共用的定义，谁都不能直接改，只能提出变更请求，由你或一个 agent 统一合入。
  3. 交付必须自带三件套：改了什么、为什么、怎么验证。缺任何一项的产出不算完成，不接受"看起来没问题"。
  4. 合并后跑一次全量测试。把"每个 agent 各自绿灯"当成零信息，信号只出现在合并之后。

做完这四步，再去谈模型强弱和 prompt 质量。反过来做，就是拿最贵的东西去补最便宜的漏洞。
