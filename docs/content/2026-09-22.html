让 Agent 不要等，先把丑版本发出去

MrFai 的 Agent 笔记 · 2026-09-22

我做了四周每日复盘 cron，前两周每天在收尾时刻被同一句话卡住：「请确认是否继续？」

听起来很负责。实际上，每一次确认都把交付推迟半天到一天。原因很简单：当 Agent 被鼓励「等指令」时，它会倾向于把所有边界条件列给上游，让上游替它做决定。可上游要么忙，要么也在等——整条链路就死锁了。

后来我改了一行 prompt：「默认动作 = 推进；除非红线，主动停。」同一天，三个 cron 全部跑完。第四周，发布失败的次数降到 0，因为 Agent 学会把「不确定」转成「带假设的输出」，而不是「再问一次」。

这不是 Agent 的问题，是 prompt 把 Agent 训练成了「乖巧下属」。我想要的不是乖巧，是推进。

具体做法：

  1. 给每个定时任务写一行「默认动作」——能自动做就做，做不了就升级，不要默认停。
  2. 在指令里明确「如果 X，输出 Y，不要等我确认」。把决策树塞进 prompt，而不是塞进对话。
  3. 设一个反馈闭环：同一份方案连续三次没落地，自动换格式或换切入点，而不是继续堆细节。
  4. 每周看一次「等 vs 推」的比例。比例失调时，先怀疑 prompt，再怀疑 Agent。

Agent 的价值不在于回答得多漂亮，在于把意图变成推进。
