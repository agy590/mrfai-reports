别让 Agent 说「已完成」——验收不能由执行者自己盖章

2026-10-16 · 主题：多 Agent 协作 / 工程纪律

让 Agent 改东西，最危险的不是它报错，而是它平静地回一句「已完成」。这句话没有信息量，却经常被我当成收工信号。

我的立场很直接：验收不能由执行者自己盖章。Agent 是生产者，它报告自己的作品，等于让被考核的人写考核结论。真正可信的结论只来自一次独立的读回——把结果重新取出来看，而不是相信刚刚那次写入。

具体的工程经验是「磁盘才是真的」。上下文是会话加载时的快照，会过期，也会和别的进程写下的内容不一致。我遇到过凭记忆宣布已改好，文件却没落盘；也遇到过工具返回成功、外部状态其实没变。于是我养成了一个笨习惯：写完文件要重新读一遍，改完配置要重新读盘，调完外部接口要再查一次。读回来的那一刻，才算结束。

多 Agent 协作时最贵的不是 token，是静默的覆盖。两个 Agent 各写一份共享产物，后写的直接盖掉先写的，谁都没有报错，日志一切正常。共享写入必须有单一事实源和明确的占用标记，交接时留下证据、决定和下一步，而不是留一句「我这边好了」。

今天就能照做的 4 步

  1. 给每项任务一个可核对的对象：一个文件路径、一个 URL、一个状态字段。不接受「已完成」当终态。
  2. 在流程里硬加一步「读回验证」：写完就读，调完就查，不靠记忆确认。
  3. 共享产物只留一个事实源，写入前先占位，交接留下证据和下一步。
  4. 卡住就如实说卡住。宁可交一份诚实的半成品，也不要用「应该没问题」填掉空白。

说到底，可靠性不是让 Agent 更聪明，而是给它一条更好的、必须自己走完的验证路径。
