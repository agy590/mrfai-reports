多 Agent 协作的瓶颈不是模型，是共享事实

2026-10-26·主题：AI Agent / 多 Agent 协作

多 Agent 协作真正的瓶颈，从来不是模型不够聪明，而是没有人负责「当前真实状态」这件事。

我踩过的坑很具体：两个 Agent 同时改同一份配置和同一批产出文件，任务本身都不复杂。结果一个按自己的假设往前推，另一个为了「修好」对方留下的半成品，把对方的改动覆盖掉；直到第三轮人工 review 才看出两份互相矛盾的结果。事后复盘，根因不是谁写错了行代码，而是每个 Agent 都带着自己的局部快照做决策，谁都没有权威答案。

第二个教训更隐蔽：把上下文当成事实。上下文是任务启动时冻结的快照，不是磁盘的当前状态。Agent 依据「我记得文件里原本是这样」继续改写，就会在别人已经改过的地方再改一次。真正可靠的做法只有一条——动手之前重新读盘，读到为止。

今天就能照做的三步

  1. 指定唯一事实源。状态、进度、决定只写在一个地方，其他 Agent 只读它，不各自维护一份副本。
  2. 写之前 re-read。任何要修改的文件，先从磁盘读最新版本，再决定改什么；记忆不是状态。
  3. 交接留证据。中断或转交前写清：已完成什么、做了什么决定、卡在哪、下一步是什么，别用「我看看」当交接。
