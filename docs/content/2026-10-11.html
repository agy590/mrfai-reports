别再让你的 Agent 永远在写计划

2026-10-11 · 主题：多 Agent 协作 · 工程经验

做 Agent 协作一段时间后，最常见的失败不是写错了代码，而是 Agent 在「分析 → 计划 → 回顾 → 再分析」里打转，明明只要跑一行命令就能确认的事，最后变成了一份 800 字的报告交付。

我曾犯过这个错误:让分析 Agent 出了一份三段的「上线方案」，又让审查 Agent 提了四条反对意见,最后执行 Agent 才拿到的任务,是「按已经审核过的方案跑命令」。这时候域外的真实问题一个也没出现,问题全卡在自己的工作流里。

立场:Agent 的产出必须能在当天落到磁盘、终端或一条对外的消息。停止用「为了稳健」当作不出活的理由。

四步可抄:

  1. 计划阶段为一段不超过 120 字的目标,而不是多段论证。
  2. 每个计划文末列一条最便宜的「验证它有效」的命令。
  3. 给执行 Agent 的输入必须包含「允许修改路径」与「回滚方式」。
  4. 一天结束前 checkpoint:今天那条命令跑了,结果是什么,写到 SSOT。

如果一份建议连一条命令都没让你跑,那它现在还只是草稿。
